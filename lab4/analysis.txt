1. QUERY USED FOR ANALYSIS

EXPLAIN ANALYZE
SELECT c.name,
       o.order_id,
       o.total_amount
FROM orders o
INNER JOIN customers c
ON o.customer_id = c.customer_id
WHERE o.status = 'delivered';


2. OUTPUT

 Nested Loop  (cost=0.14..9.69 rows=1 width=238) (actual time=0.074..0.150 rows=20 loops=1)
   ->  Seq Scan on orders o  (cost=0.00..1.38 rows=1 width=24) (actual time=0.027..0.041 rows=20 loops=1)
         Filter: ((status)::text = 'delivered'::text)
         Rows Removed by Filter: 10
   ->  Index Scan using customers_pkey on customers c  (cost=0.14..8.16 rows=1 width=222) (actual time=0.004..0.004 rows=1 loops=20)
         Index Cond: (customer_id = o.customer_id)
 Planning Time: 1.958 ms
 Execution Time: 0.318 ms


3. OUTPUT EXPLANATION

- Seq Scan on orders → scans orders table to find delivered orders.
- Rows Removed by Filter → 10 orders didn’t match the status and were skipped.
- Index Scan using customers_pkey → quickly finds matching customer using primary key index.
- Nested Loop Join → joins each order to its customer one by one.
- Planning Time → 1.958 ms to plan the query.
- Execution Time → 0.318 ms to run the query.

4. PERFORMANCE INSIGHT

- Query runs efficiently because customer_id is indexed.
- If the dataset grows, PostgreSQL may switch to Hash Join or Merge Join.

5. CONCLUSION

Using EXPLAIN ANALYZE helps developers understand how queries are executed,
check if indexes are used, and optimize slow queries.
